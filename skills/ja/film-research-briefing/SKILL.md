# SF映画理解ブリーフィング

映画を未見または再視聴できない状況でも、作品内容、世界設定、他者の解釈、そこから開かれる未来への問いを混同せずに把握できる成果物を作る。目的は作品単体の理解であり、過去の論文や研究プロジェクトへの接続ではない。利用者が明示した場合にだけ、別枠で特定テーマとの接続を扱う。`evidence_domain` の分離は映画と現実の比較を禁止するためではなく、学術論文で映画内設定を現実の事実命題として持ち込まないための追跡管理である。

## 基本原則

- 検索結果、タイトル、サムネイル、LLM の記憶は候補発見にのみ使う。内容上の主張は、開いた原資料を読んで出典ノートへ実体化してから書く。
- 「作品内で起きること」「世界設定上のルール」「制作者や出演者が述べたこと」「批評者の解釈」「本調査から生まれた未来への問い」を分離する。
- YouTube やブログは有用な二次資料として扱う。ただし、その解釈を作品内の事実や制作者の意図へ昇格させない。
- 映画を見ていない場合、そのことを明記する。映像表現、編集、音響、演技、曖昧な場面の分析を、あらすじ資料だけから確定しない。
- 著作権、サイト規約、アクセス制限を尊重する。保護を回避せず、必要最小限の短い証拠箇所と要約を保存する。取得できない資料は `metadata-only` と記録する。
- 成果物は無保証の調査支援である。重要な主張は利用者が作品本編と一次資料で確認する。

## ワークフロー

### 1. 調査条件を固定する

作品名、公開年または版、ネタバレ許容度、利用可能時間、知りたいことを確認する。同名作品やリメイクがあれば対象を識別する。情報がなければ、全編ネタバレ可・5分で読める作品理解を既定値とし、その仮定を冒頭に示す。利用者の過去の論文や研究テーマを探索・参照しない。

初回は次のスクリプトで調査ディレクトリを作れる。

```bash
python3 <skill-dir>/scripts/init_topic.py \
  --root . --topic-id terminator-skynet --title "ターミネーターとスカイネット"
```

### 2. 資料候補を広く探す

最低限、次の異なる経路を検討する。

1. 作品そのものに近い資料: 正規配信・上映、脚本、公式字幕、公式あらすじ
2. 制作の一次資料: 監督・脚本家・出演者のインタビュー、音声解説、制作資料
3. 研究・批評資料: 査読論文、書籍、映画機関、署名付き批評
4. 説明資料: YouTube の解説・動画エッセイ、ブログ、百科事典

検索は発見段階であり、検索スニペットを根拠として記録しない。資料の選び方と主張別の証拠要件は必ず [source-policy.md](references/source-policy.md) を読む。

### 3. 原資料を開いて出典ノートを作る

採用する各資料について、本文・字幕・トランスクリプト・動画内容を実際に確認する。取得日、著者、公開日、URL、資料種別、グラウンディング状態、ページ・節・タイムコードを記録する。

```bash
python3 <skill-dir>/scripts/create_source_note.py \
  --topic docs/terminator-skynet \
  --source-id S001 \
  --title "資料タイトル" \
  --url "https://example.com/source" \
  --source-kind video-essay \
  --evidence-level critical-secondary \
  --evidence-domain critical-discourse \
  --creator "作成者名" \
  --grounding-status grounded
```

YouTube、ブログ、字幕を扱う場合は [web-source-acquisition.md](references/web-source-acquisition.md) を読む。全文転載はせず、主張の検証に必要な短い証拠箇所、位置情報、忠実な要約を残す。

### 4. 主張を型付けして照合する

主張を `plot`、`worldbuilding`、`production`、`creator-intent`、`reception`、`interpretation`、`real-world-fact`、`present-day-comparison`、`future-question` のいずれかに分ける。出典の不一致は平均化せず、両論と未確定点を残す。各出典ノートには `evidence_domain` を付け、映画内設定を現実の事実として学術論文へ持ち込まない。現実との比較や映画から着想を得た問いは可能だが、比較・解釈・問いとして明示し、映画の設定を現実の根拠にしない。

- `confirmed`: 要件を満たす資料で確認できた
- `provisional`: 二次資料のみ、または資料間に未解決の差異がある
- `attributed`: 特定の論者による解釈として帰属を明記した
- `synthesis`: 複数資料から本調査で導いた整理、現在との比較、未来への問い。作品や論者の主張として書かない

構造と記法は [artifact-schema.md](references/artifact-schema.md) に従う。

### 5. 時間制約付きブリーフィングを書く

既定の成果物は `docs/<topic-id>/briefings/<work-id>.md` とし、次を含める。

1. 読了時間、ネタバレ範囲、作品本編の確認状況
2. 30秒要約
3. 物語の因果鎖と結末
4. 登場人物・勢力・世界設定のルール
5. 作品が扱う中核テーマと代表的な解釈
6. 公開当時の未来像と、現在から見た実現・未実現・変形
7. 作品から自然に生まれる未来への問い（答えを一つに閉じない）
8. 解説者間の一致・不一致と未確認点
9. 本編を見るなら優先したい場面または論点
10. Claim ledger と Source ledger

`Claim ledger` と `Source ledger` はブリーフィング本文の末尾に置く。台帳の後ろに解説、視聴ポイント、注意書きなどの本文を追加しない。順序は `Claim ledger`、続いて `Source ledger` とし、Source ledger の最後の行をファイル末尾とする。

現代との比較は作品理解を助ける範囲に留め、作品を「予言が当たった／外れた」だけで評価しない。たとえばスカイネットを AGI と呼ぶなら、作中で描かれる能力、現在その語に与える意味、描写されない能力を分ける。未来への問いは断定的な予測にせず、作品のどの設定から生まれた問いかを示す。

### 6. ゲートを通す

```bash
python3 <skill-dir>/scripts/check_grounding.py docs/<topic-id>
```

FAIL があれば、出典ノートの追加、主張ステータスの弱化、帰属の明示のいずれかで解消する。WARN は残せるが、ブリーフィングの「限界・未確認点」に転記する。

## 完了条件

- 各内容主張が Claim ledger から出典ノートへ追跡できる
- 作品事実、世界設定、制作者の発言、他者の解釈、現在との比較、未来への問いが明示的に分離されている
- 未見・未取得・自動字幕・版違いなどの限界が読者に見える
- 短時間で作品単体の要点を把握でき、想像を広げ、必要なら本編や原資料へ戻れる
- 検査スクリプトが PASS（WARN がある場合は説明済み）
